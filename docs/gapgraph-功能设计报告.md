# 《GapGraph / 缺口图谱》功能设计报告

> 备考者「掌握度可视化 + 自动补习计划」桌面软件 · 功能落地规格
> 版本 v1.0 · 面向 2026 郑轻中源黑客松（整体主题：身边的小问题，值得一个新产品；特别赛道一：学习陪伴）
> 定位：本文件是**功能与算法规格**，不是代码。开发排期、数据模型、验收标准均已给到可直接执行的粒度。

---

## 0. TL;DR：对你原方案的三条关键改动

| # | 你的原设计 | 建议改成 | 为什么 |
|---|---|---|---|
| 1 | 「AI 根据用户描述**生成**一张知识网络/思维导图」 | **考纲骨架（确定性、可版本化）+ AI 内容填充 + 个人掌握叠加层**，三层分离 | LLM 从零画图必然漏考点、每次跑结果不同、无法复现、无法核对。而"考点全覆盖"恰恰是备考的硬需求。骨架由预置考纲包提供（0 幻觉、0 延迟、0 成本），AI 只负责**在骨架上写内容**和**补充超纲关联** |
| 2 | 「用户告诉 AI**自己学会了什么**」 | **自评（三档粗标）+ 10 分钟自适应诊断测 双通道融合**，冲突时以行为证据为准 | 用户对自己掌握程度的判断系统性偏高（元认知偏差）。你痛点的后半句"用户对自己的掌握程度也不了解"已经说明自评不可信——不能用不可信的输入当唯一输入 |
| 3 | 「AI 分析答题情况，**优化图结构**」 | AI 不再改**结构**，只写**节点的内容**与**题目→考点的多标签映射**；结构只由三件事改变：考纲、用户手动整理、AI 提议+用户确认 | 让 LLM 反复重排图结构 = 用户每次打开图都变样，导航记忆归零。图是用户的"心理地图"，稳定性比"智能"重要得多 |

**一句话产品定义**：
> 它不是"AI 生成思维导图"，而是**一张会随做题变色的考纲地图 + 一个每天告诉你今天该补哪 3 个洞的任务队列**。

## 1. 用户画像细化

### 1.1 三个亚型（功能优先级不同，不能一套 UI 打天下）

| 维度 | A · 中考型 | B · 高考型 | C · 考研型 |
|---|---|---|---|
| 年龄 | 14–15（**未成年人，隐私红线**） | 17–18 | 21–24 |
| 典型学科 | 数理化 + 语英史道法 | 9 科选 6 | 数学/408/法硕/管综 |
| 题型结构 | 选择/填空为主，主观题少 | 选择 + 大题，步骤分 | 选择 + 大段主观/计算证明 |
| 题库可得性 | 高（教辅、真题结构化程度高） | 高 | 中（自命题校差异大，真题零散） |
| 主要痛点 | **不知道自己哪里不会**，被家长/老师推着走 | **板块性缺口**（如"立体几何一到大题就崩"） | **范围失控**（大纲外的自命题、跨章节综合） |
| 时间预算/天 | 1–2 h（在校，碎片） | 2–3 h | 4–8 h（全职备考） |
| 图谱层级偏好 | 浅（3 层，看得懂） | 中（4 层，到题型） | 深（4–5 层，到方法/定理变体） |
| 关键差异化功能 | 家长视角只读摘要、错题打印 | 板块热力图 + 抢分模式 | 自命题院校考纲导入、跨章依赖权重 |

> **产品策略**：v1 主打 **B 高考型**（题库最规整、demo 最有冲击力、评委最能共情），A 与 C 用"考纲包 + 层级深度"参数适配，不做独立界面。

### 1.2 真实使用场景（决定交互形态）

1. **听完课当晚（20–40 min，桌面）**：打开软件 → 点今天学的 2 个节点 → 自评"学过但不会" → 做 5 道诊断题 → 图谱上两片区域变红 → 明天任务队列自动生成。**这是最高频、最必须做顺的场景**。
2. **周末复盘（60–90 min）**：看热力图 → 按"缺口优先级"从上往下清 → 把 AI 讲明白的方法收藏成卡片。
3. **考前 2 周（每天 20 min）**：切抢分模式 → 只练高权重高频节点 → 预估分区间收敛。
4. **碎片时间（手机/平板）**：**本产品不做移动端**，v1 明确"桌面 + 导出 Anki/PDF 错题单"作为移动替代。
5. **无网环境（考场/学校机房/断网自习室）**：**核心链路必须离线可用**（骨架图、做题、掌握度计算、任务队列全本地；仅 AI 讲解与主观题批改需要网）。这条同时是黑客松硬要求——"演示不依赖不稳定网络"。

### 1.3 反向画像（明确不服务谁，避免功能蔓延）

- 完全零基础、需要从课本第一章讲起的人 → 本产品假设"已听课/已学过一遍"，不做零基础教学。
- 只想无脑刷题、不要任何诊断的人 → 用 Anki/猿题库更合适。
- 需要真人答疑、需要监督陪伴的人 → 本产品不出"班主任学管"人格。
- 主要用手机学习的人 → v1 不做。

### 1.4 用户故事（完整走一遍，用来校验功能是否有断点）

> 小林，高三，数学 90 分想上 120。听完"基本初等函数"这章。
> 1. 打开软件，选「2026 高考 · 数学」考纲包 → **30 秒内出现 42 个节点的完整骨架**（他一个字都没输入）。
> 2. 软件问"这一章你学到哪了？"→ 他勾了 5 个节点标"学过"、2 个标"没学过"。
> 3. 点「10 分钟摸底」→ 12 道自适应题（从 p≈0.7 难度起）→ 做完，图谱上有 3 个节点变红、1 个变黄、1 个变绿。
> 4. 点最红的「指数函数与对数函数比较大小」→ 右侧面板：掌握度 0.31（数据置信度中）、3 道错题可回看、AI 讲解 200 字 + 一条"易混对比：底数 a>1 / 0<a<1 的单调性反转"。
> 5. 他点「问 AI」："为什么这里要取对数？"→ 回答带 3 条可收藏卡片，每张卡都挂在当前节点上。
> 6. 第二天打开软件 → **今日队列**：复习 2 个到期节点（8 min）+ 补救 1 个红节点（讲 5 min + 3 题）+ 新学 1 节（12 min）→ 总共 35 min，符合他设的 40 min 上限。
> 7. 两周后热力图从一片红变成星点红，预估分区间从 92–108 收敛到 105–118。

## 2. 痛点再解构

把"听完课复习发现板块掌握不完善、也不知道自己掌握到什么程度、无法制定计划"拆成**四个可测量的问题**——因为只有可测量，才能变成功能：

| # | 表面说法 | 根因 | 可测量目标 | 对应功能 |
|---|---|---|---|---|
| P1 | 整个知识板块掌握不完善 | **缺口不可见**：脑子里只有"会/不会"的整体感觉，没有定位到考点粒度 | 用户能在 10 秒内指出自己最薄的 3 个考点 | F1 骨架 + F3 热力图 |
| P2 | 不知道自己的掌握程度 | **没有测量**：从未做过分考点的定量评估；自评系统性偏高 | 每个节点的估计误差可量化（置信度 + 区间），不以"感觉"呈现 | F2 诊断 + F3 三轴模型 |
| P3 | 无法制定补习计划 | **优先级不会算**：不知道该先补哪个，也不知道每天该做多少 | 每天给出 ≤3 项、总时长可控、可按"权重×缺口×依赖"排序的具体动作 | F8 任务队列 |
| P4 | 复习没有回收闭环 | **做了题不归因**：错了只知道错，不知道错在概念/记忆/审题/计算 | 每道错题必须归到一个错因 + 一个考点，错因决定干预方式 | F7 错因归因 |

> 关键判断：**P2 是整个产品的技术核心，P3 是留存核心，P1 是获客核心（第一眼冲击力）**。三者都由"题目 → 考点映射 + 掌握度模型"这一根地基支撑。地基没打好，上面三个都变成"看起来很酷的图"。

## 3. 对原方案的体检：保留 / 改造 / 砍掉

### 3.1 保留（这三点是对的，且是差异化）

- ✅ **以考点为节点、可下钻**的图结构 —— 对"板块复习"的心智模型完全正确，比线性目录强。
- ✅ **做题反哺图** —— 用行为数据而非自评来更新掌握度，方向正确。
- ✅ **对话收藏到知识库并绑定节点** —— 这是把"一次性 AI 问答"变成"可复用资产"的关键设计，绝大多数 AI 学习工具缺这一环。

### 3.2 改造（原设计里的坑）

| 原设计 | 坑 | 改造方案 |
|---|---|---|
| AI 生成整张图 | 幻觉漏考点、不可复现、首屏等待 30 s+、demo 现场网络抖动就翻车 | **三层图**：① 考纲骨架（本地 JSON，预置 6 科）② 节点内容（AI 生成 + 缓存，可手动编辑）③ 掌握叠加层（本地计算）。首屏永远 <1 s |
| 用户口述"学会了什么" | 输入不可信、口述漏项、LLM 理解偏差 | 三入口：**选考纲 → 自评打标（三档）→ 诊断测校准**。自评只给初值，行为数据有权覆盖 |
| AI 优化图结构 | 图每次变样，用户找不到昨天看到的节点 | 结构变更收归三处：考纲版本升级（显式提示 diff）、用户手动整理、AI **提议**合并/新增且需用户确认 |
| 节点"点击展开查看" | 展开后是一段 AI 散文，看完就忘，无法验证 | 节点面板 = **六区块**（讲解 / 题目与错题 / 掌握曲线 / 易混对比 / 笔记卡片 / 子图），每块都有可操作项 |
| 节点可展开为下一层子图的根 | 无限下钻 → 迷路、重复节点、结构爆炸 | 深度上限 4（可配到 6）+ 面包屑 + 子图必挂父链接 + 三个整理动作（提升/合并/重挂）+ 近义检测 |
| "分析答题情况" | 一题多考点时无法归因；蒙对会污染数据 | **多标签加权分摊** + **答题时长阈值识别"疑似猜对"**（<3 s 且答对 → 不计入掌握证据） |

### 3.3 砍掉（v1 不做，写进路线图而非 MVP）

- ❌ 手写拍照 OCR 自动切题（准确率不稳，demo 现场风险高）→ v1 只做**粘贴文本**切题。
- ❌ 主观题 AI 自动评分（考研/A 类需求）→ v1 做"采分点自评 checklist"，AI 只给提示不判定。
- ❌ 多端同步 / 云账号 → v1 纯本地 SQLite + 文件导出。
- ❌ 社交、排行榜、学习搭子 → 与"考前焦虑"用户的心态冲突。
- ❌ 语音问答 → 噪声环境识别差，投入产出低。

## 4. 核心设计原则（七条，冲突时按序仲裁）

1. **骨架确定性，内容生成性**：结构来自考纲（可核对、可版本化），文字来自 AI（可缓存、可编辑）。
2. **证据优先于自评**：任何"我觉得我会了"都能被一次 3 题的小测推翻，反之亦然。
3. **不呈现虚假精度**：样本 <3 题显示"数据不足"，掌握度用 5 档色带 + 区间，不显示"73.4%"这种假精确。
4. **每天只让用户做 3 件事**：任务队列硬上限 3 张卡（可手动加），超时即止。备考者的敌人是过载，不是懒惰。
5. **离线可用，AI 可降级**：关掉网络，软件仍是完整的"骨架图 + 做题 + 热力图 + 队列"。
6. **图是心理地图，稳定压倒智能**：结构不做自动重排；任何自动变更必须可撤销。
7. **一切可追溯**：每道题、每张卡、每次 AI 对话都挂到节点；点节点能倒查"为什么我认为我不会"。

## 5. 信息架构与主界面

### 5.1 五个视图

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏：科目切换 │ 考试倒计时 87 天 │ 今日进度 2/3 │ 搜索 │ 设置        │
├──────────────┬───────────────────────────────────────┬───────────────┤
│ ① 左栏        │ ② 中央：知识网络（主视图）              │ ③ 右栏：节点   │
│              │                                       │    详情面板    │
│ 今日任务(3)   │      [函数]                           │  ┌──────────┐ │
│ ├ 到期复习 2  │       ├─[基本初等函数] ●红            │  │讲解        │ │
│ ├ 缺口补救 1  │       │   ├─[指数函数] ●黄            │  │题目 5 错 3 │ │
│ └ 新学 1      │       │   ├─[对数函数] ●红            │  │掌握曲线 ↗  │ │
│              │       │   └─[幂函数]   ○未测           │  │易混对比    │ │
│ 视图切换      │       └─[三角函数]  ●绿               │  │笔记卡 2    │ │
│ ▸ 图谱        │                                       │  │子图        │ │
│ ▸ 热力矩阵    │  面包屑：数学 › 函数 › 基本初等函数    │  └──────────┘ │
│ ▸ 大纲        │  图例：●红=缺口 ●黄=不稳 ●绿=稳 ○灰=未学│              │
│ ▸ 错题本      │                                       │              │
│ ▸ 知识库      │                                       │              │
├──────────────┴───────────────────────────────────────┴───────────────┤
│ 底栏：本次会话 +3 题 / 覆盖 12→13 个考点 / 缺口 -1 个                 │
└──────────────────────────────────────────────────────────────────────┘
```

- **① 今日任务**（默认首屏，不是图谱！）：3 张卡，每张卡 = 一个动作 + 预估分钟 + 完成按钮。**这是留存的钩子**。
- **② 知识网络**：DAG 分层布局（**不要用力导向**，前置关系必须能一眼看出）。
- **③ 节点详情面板**：宽 380–420 px，六区块折叠。
- **④ 热力矩阵**（第二视图）：行=考点、列=能力维度（记忆/理解/应用/迁移），格子颜色=掌握度。**这个视图比图更"顾问感"，尤其适合截图放路演 PPT**。
- **⑤ 大纲视图**：树形列表，可与图谱联动高亮。图谱看结构，列表找节点，两条路径都要有。

### 5.2 首次使用流程（必须 ≤5 分钟到第一张图）

```
启动 → 选考试类型（高考/中考/考研）→ 选科目 → 选考纲包版本
  → [关键] 询问"这科你学到哪了？" → 三档批量打标（按章节分组，勾选即可）
  → 立即出图（骨架 + 自评色）→ 提示"想更准？花 10 分钟做个摸底"
  → [可跳过] 诊断测 → 图更新 → 进入今日队列
```

> 设计要点：**任何一步都允许跳过且能回到主界面**。绝不做 10 步 onboarding 问卷。

## 6. 功能规格（F1–F12）

每节格式：目标 → 交互 → 状态/边界 → 验收。

### F1 · 考纲骨架与学习范围设定

**目标**：让用户一个字都不输入，就得到一个完整、可信、可核对的知识结构。

**数据来源**：预置考纲包（JSON，随包分发，不入库也能读）。一个考纲包 = 学科 × 考试 × 年份/版本。

**考纲包结构（示意）**：

```jsonc
{
  "packId": "gaokao-math-2026",
  "title": "2026 高考数学（全国卷）",
  "totalScore": 150,
  "nodes": [
    {
      "id": "n_func_elem",
      "parentId": "n_function",
      "name": "基本初等函数",
      "kind": "concept",              // concept | skill（题型/方法）
      "depth": 2,
      "examWeight": 0.85,             // 考频×分值归一化 0.0–1.0，人工标定
      "prereq": ["n_function_def"],   // 前置节点 id（构成 DAG）
      "confusable": ["n_trig"],       // 易混节点（用于对比训练）
      "typicalQuestions": ["比较大小", "单调性判断", "图像变换"]
    }
  ]
}
```

**交互**：
- 支持导入自定义考纲（JSON / 纯文本大纲，用缩进识别层级）→ 考研自命题院校必需。
- 支持"裁剪范围"：勾掉不考的章节（考研尤其常见），裁剪后这些节点从热力图与队列中排除，但仍在图谱中灰显。
- 考纲版本升级时，弹 **结构 diff**：新增 N 个节点 / 删除 M 个 / 改名 K 个，用户确认后才合并。

**边界**：考纲缺失时（用户选"其他"）→ 走"空白包"：用户输入 3–10 个章节名，AI 生成 3 层骨架并**明确标注为 AI 推测、可编辑**。

**验收**：新用户选完考纲到看见完整骨架 ≤ 3 s（本地读 JSON，无网络请求）。

### F2 · 初始校准：自评 + 自适应诊断

**目标**：用最低用户成本获得一个可用的初始掌握估计。

**入口三选一（可叠加）**：

| 入口 | 成本 | 精度 | 说明 |
|---|---|---|---|
| 自评批量打标 | 60 s | 粗（±0.25） | 按章节折叠，每节点三档：没学过 / 学过不会 / 会 |
| 10 分钟摸底（推荐） | 10 min | 中（±0.12） | 12–15 题自适应，覆盖范围内高权重节点 |
| 直接做题（自然累积） | 0 | 渐进 | 什么都不做，靠日常做题慢慢填充 |

**三档 → 初值映射**：没学过 → `K=0, M=0`；学过不会 → `K=0.5, M=0.25`；会 → `K=1, M=0.6`（注意：自评"会"只给 0.6，不给 1.0——把余量留给行为证据）。

**自适应选题（见 §7.5）**：每题选当前 `p(答对)≈0.7` 的题，答对则升难度，答错则降并**自动下钻到父节点/前置节点**（"你错的不是这道题，是它依赖的复合函数定义"）。这条下钻逻辑是本产品的"聪明感"来源。

**诊断结束输出**：一张"缺口卡片"——最薄的 3 个节点 + 建议的第一张任务卡。**不做长篇报告。**

**边界**：题库不足时（节点无题）→ 降级为"回忆式自测"（用户打字复述要点，AI 按采分点提示缺什么）。

**验收**：15 题诊断后，若某节点 n≥3 题，其 M 与"再做 5 题后的 M"偏差 ≤0.15。

### F3 · 掌握度画像（三轴 + 置信度）

**目标**：把"掌握程度"从感觉变成**可解释的三维量**，且永远不呈现虚假精确。

**三轴定义**：

| 轴 | 符号 | 含义 | 取值来源 |
|---|---|---|---|
| 覆盖 K | Knowledge coverage | 是否学过 / 见过 | 自评 + 是否出现学习行为（看讲解、做题） |
| 能力 A | Ability | 会做多难的题 | 答题正确率（难度加权 + 时间加权 EWMA） |
| 保持 R | Retention | 现在还记得多少 | 间隔天数与记忆稳定性 |

**展示规则**：
- 节点主色 = `M`（综合掌握度）5 档：0–.2 红 / .2–.4 橙 / .4–.6 黄 / .6–.8 浅绿 / .8–1 绿
- 未测（n=0）→ 灰色描边，**不猜**
- 置信度 `conf < 0.4` → 节点加虚线边框 + 悬浮提示"数据不足，去测 3 题"
- 详情面板显示 **区间**（如 `0.28–0.41`）而非单点，区间宽度 ∝ 1/√n

**边界**：不同科目/考试难度不可横向比较（高考数学 0.6 与中考数学 0.6 不代表同等水平）→ 阈值全部按考纲包配置，不硬编码。

**验收**：任意节点都能回答"为什么是这个颜色"——点开即见 3 条证据（哪几题、何时、对错）。

### F4 · 知识网络（图谱主视图）

**目标**：一眼看出"我这一章哪儿塌了"。

**节点与边**：

| 类型 | 说明 | 视觉 |
|---|---|---|
| `concept` 概念节点 | 定义、定理、性质 | 圆角矩形 |
| `skill` 题型/方法节点 | "比较大小"、"含参讨论" | 菱形/标签形 |
| `prereq` 前置边 | A 是 B 的前提 | 实线箭头 |
| `part-of` 层级边 | 父子 | 树线 |
| `confusable` 易混边 | 双向虚线（红） | 虚线 |
| `related` 相关边 | 弱关联 | 细灰线 |

**布局**：**分层 DAG 布局**（dagre / ELK layered），横轴 = 层级，纵轴 = 同层顺序。前置关系必须几何可见。**禁止力导向**（力导向会把"函数→导数"这种因果关系打散）。

**层级约束（解决"无限下钻"）**：
1. 默认渲染到 L2；点节点展开其 L3 子图（子图替换主画布，面包屑返回）。
2. **深度上限 4**（设置可调至 6），到上限时"展开为子图"按钮禁用并提示"建议在笔记里细分"。
3. 子图根节点必须**保留一条回到父节点的引用边**（跨图不会变孤儿）。
4. 三个整理动作（右键菜单）：
   - **提升为同级**：把子节点拖到父层级（解决"分错层"）
   - **合并到…**：选另一个节点，合并后票数/证据按权重合并（解决重复节点）
   - **删除并重挂**：删节点时把其子节点与证据转移到指定节点
5. **近义检测**：编辑距离 + 命名相似度 >0.8 的两个节点标"疑似重复"，出黄色小圆点提示（不自动合并）。

**性能分级**（本机为 Intel Arc 核显 + 32 GB）：

| 节点数 | 渲染方案 |
|---|---|
| ≤300 | SVG（React Flow / D3 均可），可做精细动效 |
| 300–2000 | **Canvas：Cytoscape.js + dagre**（推荐，MVP 就用这个） |
| >2000 | 需 WebGL（Sigma.js）或**按层聚合**（推荐聚合，别换引擎） |

**交互细节**：
- 单击 = 选中并开右栏；双击 = 展开子图；右键 = 整理菜单。
- 悬停显示 mini 卡（掌握度 + 题数 + 最近一次对错）。
- 支持"只看缺口"过滤（M<0.5 或 conf<0.4）。
- 支持"错误热力"模式：边按错误传递次数着色（A→B 前置失败率高 → 边变红），**这是"结构随数据变化"的正确表达形式**：不改拓扑，只改视觉权重。

**验收**：500 节点图在 60 fps 下平移缩放不卡（核显无硬件加速禁用时 ≥30 fps）；展开/收起 <200 ms。

### F5 · 节点详情面板（六区块）

| 区块 | 内容 | 可操作 |
|---|---|---|
| ① 讲解 | 3 段：是什么 / 怎么考 / 易错在哪。**带缓存**，同一节点只生成一次 | 重新生成、编辑、标记"不准"、字数切换（简/详） |
| ② 题目与错题 | 该节点关联题目列表（含来源、难度、最近结果） | 开始练习（3/5/10 题）、加题、看解析 |
| ③ 掌握曲线 | 三轴小图 + 最近 10 次作答时序 | 点任意点跳回那次作答 |
| ④ 易混对比 | `confusable` 边对端节点的**差异表**（3–5 行，如"底数范围 vs 单调性"） | 来一组对比题（专门打混淆） |
| ⑤ 笔记/卡片 | 收藏的卡片 + 手写笔记 | 新建卡、从对话收藏、置顶、导出 |
| ⑥ 子图 | 若已有子节点，列出并可展开为根 | 展开、在此新建子节点 |

**边界**：无题库节点 → ② 显示"回忆式自测"入口；无 confusable → ④ 隐藏（不留空框）。

### F6 · 做题与批改

**题型支持（v1）**：

| 题型 | 输入 | 判分 |
|---|---|---|
| 单选/多选 | 选项 | 确定性比对 |
| 填空 | 文本，支持多答案/等价式（`1/2` = `0.5` = `\frac12`） | 归一化后比对 |
| 判断 | 二选一 | 确定性 |
| 主观/计算 | 自由文本 或 **采分点自评 checklist** | v1：自评（AI 只给提示，不判定分数） |
| 回忆式 | 复述要点 | AI 按采分点提示遗漏项，不判分 |

**必录字段（决定整个模型质量）**：`started_at / submitted_at / duration_ms / confidence_self(用户选的"我很确定/不确定")`。
> **"我很确定但答错"** 是最有价值的信号——它意味着**错误概念已固化**，优先级要额外加权（见 §7.4 `misconception` 乘子）。这是很多题库产品漏掉的黄金数据。

**批改后立即给三件事**（不多给）：
1. 对错 + 一句话关键点
2. **错因选择**（一键，见 F7）
3. 该考点掌握度变化（"0.31 → 0.24 ↘"）

**边界**：答对但耗时 <3 s 且题为中高难度 → 标"疑似猜对"，**计入答题记录但不计入掌握证据**（不涨 M）。这个细节能显著提升模型可信度。

### F7 · 错因归因（决定干预方式的开关）

错因不是标签装饰，**它决定系统下一步给你什么**：

| 错因 | 判据（用户一键选 + 系统建议） | 系统干预 |
|---|---|---|
| 概念混淆 | 与 confusable 节点同时出错 | 出**对比题组** + 差异表卡 |
| 概念不清 | 该节点首次错、前置节点也低 | 回前置链，先补前置（不刷本题） |
| 记忆遗忘 | 曾在 2 周前做对、现在错 | 加入"到期复习"，3 天后重测 |
| 公式记错 | 用户标注 | 生成记忆卡（公式 + 一句口诀）+ 每日 1 张 |
| 审题偏差 | 用户标注（且答案与考点无关） | 生成"审题清单"卡 + 慢速练习（限时不激进） |
| 计算失误 | 用户标注（思路对） | 不出新题，只记录，**不降 M**，只降"稳定性" |
| 方法缺失 | 该题属于 skill 节点且 n 次未解 | 生成方法卡（步骤模板）+ 同类题 2 道 |
| 时间不足 | 用户标注 | 进"限时训练"队列 |
| 蒙对 | 系统自动（<3 s） | 不计证据，5 天后必测 |

**交互**：提交答案后，若答错 → 底部弹出 6 个 chip（计算失误 / 公式记错 / 审题 / 概念不清 / 方法不会 / 蒙的），**单选且可跳过**。跳过率会很高，所以默认不阻塞下一步。

**验收**：连续 5 题归因后，系统能给出至少 2 条不同的干预动作（不能永远推"再来一组题"）。

### F8 · 今日任务队列（这是留存核心，也是最容易被做砸的地方）

**目标**：把"补习计划"从一份没人看的文档，变成**3 张可点的卡**。

**队列生成（详见 §7.6）**：三类配额

| 类型 | 配额 | 内容 | 时长 |
|---|---|---|---|
| 到期复习 | 1–2 张 | 记忆到期（R 低于阈值）的节点，做 3–5 题 | 6–10 min |
| 缺口补救 | 1 张 | 优先级 P 最高的节点：讲 5 min + 3 题 | 12–15 min |
| 新学/推进 | 0–1 张 | 用户主动开启时才出现 | 15–20 min |

**硬规则**：
- 总时长 ≤ 用户设定上限（默认 40 min），**贪心装箱，装不下就少给**。
- 上限 3 张（可解锁到 5）。
- 卡可**推迟**（推到明天，记录推迟次数；同一节点连续推迟 3 次 → 换更小的动作，如"只做 1 题"）。
- 卡可**跳过**，跳过需选原因（太难 / 太简单 / 没时间）——这三个原因分别触发"降难度 / 提权重 / 拆小"。

**完成反馈**：完成一张卡 → 图谱对应区域颜色变化 + 一句话（"基本初等函数 0.31 → 0.44"）。**必须让颜色的变化被看见**，否则用户感知不到进步。

**验收**：连续开 7 天，队列 ≥5 天有内容且不重复同一节点超过 2 次。

### F9 · AI 提问与知识库卡片

**目标**：把"一次性问答"沉淀为**挂在节点上、可被复习调度的资产**。

**提问入口**：节点面板底部（自动携带节点上下文：考点名、考生考试类型、已错题摘要）。**不允许全局无上下文提问**（否则回答空泛，且无法挂载）。

**回答规范（约束 LLM 输出结构）**：

```jsonc
{
  "answer": "……（≤220 字，面向高考生，给结论 + 一句为什么）",
  "cards": [                       // 0–3 张，每张必须可独立复习
    { "type": "conclusion|method|pitfall|formula", "front": "…", "back": "…", "tags": ["…"] }
  ],
  "confused_with": ["n_trig"],     // 若回答涉及易混，返回节点 id
  "needs_more_context": false      // 真不确定时诚实置 true，前端提示"补一句你的理解"
}
```

**卡片生命周期**：
- 创建时自动绑定当前节点（可多绑，带权重）。
- 卡片与题目**共用同一个间隔重复调度器**（FSRS 简化版），所以"公式卡"和"题"在一个队列里，体验统一。
- 卡片可**升级为节点**：若一张卡明显是"一整块知识"，一键"提升为子节点"（这就实现了你说的"节点展开为下一层子图的根"——**但由内容驱动，而不是由用户摸索**，更自然）。

**知识库视图**：卡片列表 + 按节点过滤 + 全文检索（SQLite FTS5）+ 标签云 + 导出（Markdown / CSV / Anki）。

**验收**：AI 讲解同一节点第二次打开时，**直接读缓存**，P95 延迟 <100 ms（且不产生 API 费用）。

### F10 · 进度、倒计时与预估分

**目标**：给"考高分"这个终极动机一个可见的仪表盘。

- **考试倒计时**：顶栏常驻，点击进入设置（考试科目、日期、目标分）。
- **覆盖率**：`已测节点数 / 范围内节点数`，与 `加权覆盖 = Σ(w×已测)/Σw` 并列——后者更重要（只测不考的点没用）。
- **缺口收敛曲线**：每日"P>0.5 的节点数"，应该单调下降。**这是本产品最有说服力的一张图**。
- **预估分区间**：
  ```
  raw = Σ(w_i × M_i) / Σ(w_i)                 // 加权掌握度
  est = 满分 × (0.55 + 0.45 × raw)            // 保守映射：掌握 ≠ 得分，留出应试损耗
  band = est × (0.06 + 0.10 × (1 - conf_avg)) // 置信度越低，区间越宽
  ```
  显示 `est ± band`，并**明确标注"估算，非承诺"**。考前 2 周区间应明显收窄（这也是产品价值的可视化证明）。
- **抢分模式**（考前 <30 天可手动开启）：只推 `examWeight ≥ 0.7` 的节点，隐藏冷门节点，队列时长自动降到 20 min。

**验收**：完成 20 次作答后，预估分区间宽度应缩小 ≥30%。

### F11 · 题源导入（这个产品最容易断的一环，必须认真做）

**现实**：用户手里有教辅、有老师发的 PDF、有自己抄的题。**没有题源，整套模型就是空转。**

**v1 三级导入**：

| 方式 | 流程 | 工作量 |
|---|---|---|
| 单题手动录入 | 模板表单（题干 / 选项 / 答案 / 解析 / **主考点（必填）+ 次考点（0–3）** / 难度 1–5） | 20 s/题 |
| 粘贴文本批量切题 | 粘贴整段 → 按"1. / （1） / ①②" 正则初切 → 逐题确认 + 打标签 | 2 min/10 题 |
| 导入题库 JSON | 按 pack 格式批量（可给模板 + 一份 20 题的示例包） | 一次性 |

**AI 辅助**：切题后由 AI 预填"主考点/难度/答案"，**必须逐题人工确认**（防止标签污染——一旦映射错了，后面所有统计都错）。

**冷启动方案（重要）**：随包预置**每科 60–100 道种子题**，覆盖骨架里的高权重节点。用户打开即能测，不必先录题。这直接决定第一分钟能不能留住人。

**明确不做**：拍照 OCR（v1）。理由：切题准确率不稳，演示现场风险高。

### F12 · 设置、数据与隐私

- **本地优先**：全部数据在本地 SQLite；默认零上传（AI 调用只发当前节点名 + 题干文本 + 用户提问，不发整库）。
- **未成年人保护**（中考型）：无账号体系、无社交、无广告；导出/分享默认关闭。
- **导出**：全量 JSON 备份、单科 Markdown 报告、错题 PDF、Anki（`front;back;tags`）。
- **API Key**：`safeStorage` 加密存主进程，**永不进入渲染进程**；AI 请求一律由主进程代理。无 Key 时软件完整可用（AI 区块显示"未配置，手动写讲解"）。
- **数据迁移**：schema 版本号 + 迁移脚本，升级不丢数据。

## 7. 关键算法（可直接实现）

### 7.1 单题多考点分摊（防"一题连坐"）

一道题挂了多个考点，按权重分摊影响，避免做错一道综合题就把五个节点全打红：

```
答对：  ∀(n,w) ∈ tags:  Δcredit(n) += w
答错：  ∀(n,w) ∈ tags:  Δblame(n)  += w
        但主考点 w=1.0，次考点 w=0.4，且 答错时次考点影响 × 0.3
```

即：`blame(n) = w_n × (w_n == 1.0 ? 1.0 : 0.3)`。

### 7.2 掌握度三轴与更新

单节点状态：`{n_att, n_ok, A, R, K, s, last_at, conf}`

```
// 能力 A：难度加权 + 时间加权 EWMA
w_diff  = 0.6 + 0.4 * (difficulty - 1) / 4          // 难题答对更值钱
w_rec   = exp(-Δdays / 14)                          // 越近的作答权重越高
obs     = w_diff * (correct ? 1 : 0)
A_new   = A + α * w_rec * (obs - A)                 // α = 0.35

// 保持 R：提取概率（FSRS 简化）
R = exp(-Δdays / max(s, 0.5))

// 稳定性 s（天）更新
correct:  s_new = s * (1 + 1.2 * (1 - R) * w_diff)   // 越久没忘，收益越大
wrong:    s_new = max(1.0, s * 0.45)

// 覆盖 K：自评或学习行为
K = 0 | 0.5 | 1

// 综合掌握度
M = K * (0.6 * A + 0.4 * R)

// 置信度与保守估计（用于决策，不用于展示）
conf   = 1 - exp(-n_att / 4)
M_eff  = conf * M + (1 - conf) * 0.30                // 无数据时按 0.3 保守先验
```

**"我很确定但答错"惩罚**：`M` 额外 `× 0.8`，并把该节点 `misconception` 标记置真（优先干预）。

### 7.3 到期复习判定

```
due(n)  = R < 0.70  or  now > last_at + s * 0.8
到期紧急度 urgency = (0.70 - R) / 0.70
```

### 7.4 缺口优先级（"先补哪个"的唯一答案）

```
P(n) = w_exam(n)                          // 考频×分值权重
     × (1 - M_eff(n))                     // 缺口大小
     × dep_gate(n)                        // 前置闸门
     × misc_boost(n)                      // 错误概念固化 ×1.3
     × mode_factor(n)                     // 抢分模式：w≥0.7 → 1.4，w<0.4 → 0.6

dep_gate(n) = 1.0  if 所有前置 M_eff ≥ 0.6
              0.35 otherwise               // 前置没打牢，别急着刷本题
```

> 这条 `dep_gate` 是"补习顺序"的专业性来源：多数工具只会按"错了多少次"排序，而这个会**先修地基**。

### 7.5 自适应选题（近似 ELO）

```
p_pass = 1 / (1 + 10 ** ((b_q - θ_u) / 400))
θ_u(n) = 400 * log10(A / (1 - A))           // 由能力轴反推
b_q: 初次 = (difficulty - 3) * 100，之后按全站作答正确率校准

选题目标：p_pass ≈ 0.70（i+1 区）
答对：θ_u += 24 * (1 - p_pass)
答错：θ_u -= 24 * p_pass
```

题库不足时的降级：同章节随机、难度接近的题，**并明确提示"题量不足，建议导入/录入 5 道"**。

### 7.6 今日队列装箱（贪心 + 三类配额）

```
pool = due_nodes(urgency 排序) ∪ gap_nodes(P 排序) ∪ new_nodes(用户开启)
budget = 用户上限(默认 40 min)

for 类别 in [到期复习, 缺口补救, 新学]:
    取该类配额内 top 项
    动作 = 拆分(节点) → [{讲解, 5min}, {题组3, 8min}, {卡片复习, 2min}]
    按时长贪心装箱，超 budget 则停止
  最后：若总额 < budget*0.6，补一个"轻动作"（1 张卡片 + 1 题）避免"今天没事干"
```

**推迟处理**：同节点连续推迟 3 次 → 动作降级为"只做 1 题"；连推 5 次 → 从队列静默 7 天（用户明显在逃避，强推只会卸载）。

### 7.7 预估分区间

```
raw  = Σ w_i M_eff_i / Σ w_i
est  = 满分 * (0.55 + 0.45 * raw)
conf_avg = Σ conf_i / N
band = est * (0.06 + 0.10 * (1 - conf_avg))
输出：[est - band, est + band]
```

## 8. 数据模型（SQLite，可直接建表）

```sql
-- 考试与范围
CREATE TABLE exam (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, exam_date TEXT,
  subject TEXT, total_score REAL, target_score REAL
);

-- 考点（骨架 + 用户自建，同一张表）
CREATE TABLE node (
  id TEXT PRIMARY KEY,
  pack_id TEXT,                      -- 来源考纲包
  parent_id TEXT REFERENCES node(id),
  name TEXT NOT NULL,
  kind TEXT CHECK(kind IN ('concept','skill','root')),
  depth INTEGER NOT NULL DEFAULT 0,
  exam_weight REAL DEFAULT 0.5,      -- 0..1
  in_scope INTEGER DEFAULT 1,        -- 用户是否裁剪掉
  ai_generated INTEGER DEFAULT 0,    -- 标注"AI 推测，可编辑"
  created_at TEXT, updated_at TEXT
);

-- 边：前置 / 易混 / 相关
CREATE TABLE edge (
  id TEXT PRIMARY KEY,
  src TEXT NOT NULL REFERENCES node(id),
  dst TEXT NOT NULL REFERENCES node(id),
  kind TEXT CHECK(kind IN ('prereq','confusable','related')),
  weight REAL DEFAULT 1.0,
  UNIQUE(src, dst, kind)
);

-- 掌握状态（每节点一行，热路径）
CREATE TABLE mastery (
  node_id TEXT PRIMARY KEY REFERENCES node(id),
  K REAL DEFAULT 0, A REAL DEFAULT 0.3, R REAL DEFAULT 1.0,
  s REAL DEFAULT 1.0,                -- 稳定性（天）
  n_att INTEGER DEFAULT 0, n_ok INTEGER DEFAULT 0,
  conf REAL DEFAULT 0,
  misconception INTEGER DEFAULT 0,
  last_at TEXT, updated_at TEXT
);

-- 题目
CREATE TABLE question (
  id TEXT PRIMARY KEY, pack_id TEXT,
  type TEXT CHECK(type IN ('single','multi','blank','judge','subjective','recall')),
  stem TEXT NOT NULL, options_json TEXT, answer TEXT, solution TEXT,
  difficulty INTEGER DEFAULT 3,      -- 1..5
  source TEXT, created_at TEXT
);

-- 题目 ↔ 考点 多标签
CREATE TABLE question_node (
  question_id TEXT REFERENCES question(id),
  node_id TEXT REFERENCES node(id),
  weight REAL DEFAULT 0.4,           -- 主考点 1.0，次考点 0.4
  is_primary INTEGER DEFAULT 0,
  PRIMARY KEY(question_id, node_id)
);

-- 作答记录（核心事实表，只追加不修改）
CREATE TABLE attempt (
  id TEXT PRIMARY KEY,
  question_id TEXT REFERENCES question(id),
  node_primary TEXT REFERENCES node(id),
  started_at TEXT, submitted_at TEXT,
  duration_ms INTEGER,
  user_answer TEXT, is_correct INTEGER,
  self_confidence TEXT,              -- sure | unsure
  guessed INTEGER DEFAULT 0,         -- 系统判定疑似猜对
  error_reason TEXT,                 -- 见 F7 错因表
  ai_graded INTEGER DEFAULT 0
);
CREATE INDEX idx_attempt_node ON attempt(node_primary, submitted_at);

-- 卡片 / 笔记 / 收藏
CREATE TABLE card (
  id TEXT PRIMARY KEY,
  type TEXT CHECK(type IN ('conclusion','method','pitfall','formula','note')),
  front TEXT, back TEXT, tags TEXT,
  origin TEXT,                       -- ai_chat | manual | wrong_question
  due_at TEXT, s REAL DEFAULT 1.0, n_att INTEGER DEFAULT 0,
  created_at TEXT
);
CREATE TABLE card_node (
  card_id TEXT REFERENCES card(id),
  node_id TEXT REFERENCES node(id),
  weight REAL DEFAULT 1.0,
  PRIMARY KEY(card_id, node_id)
);

-- AI 内容缓存（避免重复计费，也是离线降级的关键）
CREATE TABLE ai_cache (
  key TEXT PRIMARY KEY,              -- sha256(node_id + prompt_version + task)
  payload_json TEXT NOT NULL,
  model TEXT, tokens_in INTEGER, tokens_out INTEGER, created_at TEXT
);

-- 今日任务
CREATE TABLE task (
  id TEXT PRIMARY KEY, date TEXT, kind TEXT,   -- review | gap | new | card
  node_id TEXT, question_ids_json TEXT,
  est_minutes INTEGER, status TEXT DEFAULT 'pending',  -- pending|done|postponed|skipped
  skip_reason TEXT, postponed_count INTEGER DEFAULT 0, sort_order INTEGER
);

-- 用户画像/偏好
CREATE TABLE setting (k TEXT PRIMARY KEY, v TEXT);
```

**索引导向**：热路径是"取某节点的最近 N 次作答"和"取所有 R<0.7 的节点"，因此 `idx_attempt_node` + `mastery(R)` 索引 + `mastery` 定期物化（每次作答后同步更新，不做实时计算）。

## 9. Electron 技术落地

### 9.1 进程分工（安全默认值）

```
main（Node）
 ├ db/         better-sqlite3 或 node:sqlite（Electron 44 内嵌 Node 24 可先试 node:sqlite，免 rebuild）
 ├ ai/         AI 代理（持有 API Key，safeStorage 加密）、限流、重试、缓存读写
 ├ pack/       考纲包/题库包 读取、导入、版本 diff
 ├ graph/      算法层（掌握度、优先级、队列生成）——放主进程，保证可被 vitest 直接测
 └ ipc/        白名单通道，全部 request/response 结构校验（zod）
preload
 └ 只暴露 window.api = { node: {...}, attempt: {...}, ai: {...} }（无 remote、无 fs）
renderer（React + TS）
 ├ views/     Today / Graph / Heatmap / Outline / WrongBook / Cards / Settings
 ├ graph/     Cytoscape.js + dagre（canvas 渲染）
 └ state/     zustand（轻）+ 主进程为唯一真源，渲染层只做投影缓存
```

**硬约束**：`contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、CSP 禁止 remote 脚本。

### 9.2 性能（本机 Intel Ultra 5 125H / Arc 核显 / 32 GB / 仅 1.4 GB 空闲）

- 单实例锁 `app.requestSingleInstanceLock()`；开发时 Electron + Chrome + DSH 同时开着会挤内存，`NODE_OPTIONS=--max-old-space-size=4096` 给 vite。
- 图渲染走 canvas，**不要**给 500+ 节点套 CSS 动画/阴影。
- 掌握度重算：每次作答只重算受影响节点（1–5 个），**不做全图重算**。
- userData 指到 D 盘：`app.setPath('userData', 'D:\\GapGraph-data')`（C 盘只剩 37 GB）。
- 硬件加速保留，但留 `--disable-gpu` 启动开关（远程桌面/虚拟显示器下 Arc 驱动偶发白屏——你的机器上存在向日葵虚拟显示器 `OrayIddDriver`，这个开关是必须的）。

### 9.3 打包

- `electron-vite` + `electron-builder` → `nsis`（安装版）+ `portable`（**比赛现场用这个，双击即跑**）。
- `win x64` only；`asar: true`；icon 512×512。
- 预置数据（考纲包 + 种子题）放 `resources/`，用 `process.resourcesPath` 读，**不打进 asar 内**（便于赛后替换）。

### 9.4 可验证性（让开发能自己闭环，不用人眼盯窗口）

```bash
# 开发时开放 CDP，交给 REA 检查
npx electron-vite dev -- --remote-debugging-port=9222
```

```
list_electron_targets(cdp_endpoint="http://127.0.0.1:9222")
 → inspect_electron_page(target_id)           # 读 DOM，确认节点渲染数
 → capture_electron_scenario(...)             # 点卡→答题→看颜色变化，带截图
```

- 算法层（§7 全部公式）放主进程纯函数 + `vitest` 单测，**这是保证"模型可信"的唯一手段**。
- 一条 Playwright `_electron.launch()` e2e：开图 → 答题 → 断言该节点 M 下降且颜色变成橙。

## 10. AI 工程规范

| 项 | 规定 |
|---|---|
| 输出格式 | 全部走 JSON Schema 约束（`response_format: json_object` + zod 校验），失败重试 1 次后降级为纯文本 |
| 缓存 | `ai_cache` 以 `sha256(node_id + prompt_version + task)` 为键；**讲解类永久缓存**，对话类 7 天 |
| 提示词版本 | `prompt_version` 入库；升级后不清缓存（不同版本并存），便于 A/B |
| 降级 | 无 Key / 超时 / 限流 → 显示"AI 暂不可用"，其余功能 100% 正常；讲解区提供"自己写" |
| 上下文最小化 | 只发：考纲名、节点名及路径、该节点错题题干摘要（≤3 题）、用户提问。**不发整库、不发画像标识** |
| 成本控制 | 讲解 1 次/节点（约 600 tokens）；对话单次上限 1200 tokens；预估：50 节点 × 1 讲解 + 200 次对话 ≈ 一次备考周期 ¥2–5 |
| 内容边界 | 数学/理科给结论可直接给；语文英语作文类只给结构与修改建议，不代写全文 |

## 13. 风险与反模式

| 风险 | 表现 | 对策 |
|---|---|---|
| **题源枯竭** | 图很漂亮但没题可做，模型空转 | 每科预置 60–100 题种子包；无题节点降级为回忆式自测 |
| **标签污染** | AI 自动打考点标签错一次，后面统计全错 | 标签必须人工确认；提供"该题标签有误"一键纠正并重算历史 |
| **虚假精确** | 显示"掌握度 73.4%" | 一律 5 档色 + 区间 + 置信度；n<3 显示"数据不足" |
| **图变来变去** | 用户找不到昨天的节点 | 结构不做自动重排；AI 变更需确认；提供"撤销" |
| **无限下钻迷路** | 10 层子图，回不去 | 深度上限 4 + 面包屑 + 跨图引用边 + 三整理动作 |
| **计划过载** | 一天给 9 个任务，第二天卸载 | 硬上限 3 张卡 + 时长上限 + 推迟降级 |
| **自评污染** | 用户全标"会"，图全绿 | 自评"会"只给 0.6；行为数据有权覆盖；绿色节点若答错立即降色并提示"你之前标注为已掌握" |
| **AI 依赖症** | 断网即废 | AI 只做内容与解释，算法与结构全本地 |
| **过度功能化** | 6 个视图 20 个按钮 | 首屏只有"今日队列"；图谱与热力是第二层 |
